## Morning: hitching, iOS sheet, SSID prefix, rates

- GPU/thermal/battery/Wi-Fi sysfs paths discovered once; sampling after present; `dt` capped ~33 ms; vsync via `poll(kms + touch)`.
- Network list is a bottom sheet; dim is translucent.
- Battery ADC `current_now` is ~800 ms; hot path only reads `capacity` + `status`.
- CPU/GPU/RAM/net sampled once per second (`t_occ`).
- NM profile names used to be `gemini-$SSID`; HUD showed that instead of the broadcast SSID. Strip the prefix; `iw link` is the live SSID; new profiles use the SSID as the connection name.
- Up/down rates are a separate card under Wi-Fi, 1 s window, Wi-Fi iface only.

Those HUD bits after 09:31 were hot-replaced and are **not** in the 09:31 `boot.img` until you rebuild and flash.

## Afternoon: join / password / forget

Ubuntu 26.04 stores Wi-Fi in netplan (`/run/NetworkManager/system-connections/netplan-NM-*.nmconnection`), not `/etc/NetworkManager/system-connections/`. `connection up` needs **`passwd-file`**. `nmcli up` returning 0 is not “associated to this SSID”.

`gemini-wifi-connect.sh`:

- Empty password: use a stored PSK via `passwd-file`.
- With password: `connection modify` in place (`psk-flags=0`), then `up` with `passwd-file`. Do not delete-and-recreate (that drops the PSK you just saved).
- `live_ok`: device STATE is `connected` (not `connecting`) and the in-use scan row is the target SSID.
- Wrong saved PSK → exit 3 (`密码不对`), not NEED_PASSWORD.
- Forget runs **before** radio toggles; `nmcli -w 3 connection delete`; `device disconnect` if this SSID is in use.

HUD: list row opens a **detail** sheet (`selected_ssid`). Session PSK in `known_psk_*`. iOS-style keyboard.

Host tests: `bash tests/wifi-flow/run.sh`.

### Forget spinner never ended

`wifi_forget()` set `forgetting=1` while a scan owned `job_pid`, then returned immediately on the queued retry. Fix: `gw_forget_can_start`, SIGTERM the scan (process group), start delete at once.

### First tap looked like a join failure

Switching APs leaves the old SSID up for several seconds on purpose. A **2.5 s** “fell back” check treated that as failure, and `connecting=1` skipped `iw link` so the HUD never saw the new SSID. Fix: wait up to ~12 s for the target SSID; keep info/link polling during confirm; abort scans when joining; empty-password `wait_live` miss becomes NEED_PASSWORD, not a hard fail.

### Forget still showed Connected

`sample_link()` promoted leftover IPv4 to `wifi.connected=1`; scan IN-USE still had `*`. Fix: clear UI on tap; `forget_ssid` hold until disconnect or another live SSID; `sample_link` only fills IP; script disconnects if needed.
