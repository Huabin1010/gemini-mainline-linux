## 1. PMI8994 电量计 / 充电器

### 要解决什么

用户要看整机功耗。主线 7.0 的 `pmi8994.dtsi` **没有** fuel-gauge / smbchg。6.1 umeko 上有 `qcom-battery`，可以用 `current_now × voltage_now` 估瓦数。

### 做了什么

从 msm8996-mainline 把驱动接到 overlay，并编进内核：

| 文件 | 作用 |
|------|------|
| `overlays/linux/drivers/power/supply/qcom_fg.c` | PMI8994 fuel gauge |
| `overlays/linux/drivers/power/supply/qcom-smbchg.c` + `.h` | SMBCHG 充电器 |
| `overlays/linux/drivers/soc/qcom/pmic-sec-write.c` + `include/soc/qcom/pmic-sec-write.h` | PMIC 安全写 |
| `scripts/apply-overlays.sh` | 拷驱动并补 Kconfig/Makefile |
| `overlays/linux/.../msm8996-xiaomi-gemini-local.dtsi` | `&spmi_bus { pmic@2 { charger@1000; fuel-gauge@4000; } }` |

fragment 打开：

```text
CONFIG_CHARGER_QCOM_SMBCHG=y
CONFIG_BATTERY_QCOM_FG=y
CONFIG_QCOM_PMIC_SEC_WRITE=y
```

7.0 API 适配（上游 6.1 驱动不能原样编）：

- `power_supply_config.of_node` → `fwnode`
- `devm_power_supply_get_by_phandle` → `devm_power_supply_get_by_reference`
- 本地实现 `find_closest_smaller`（7.0 没有这个宏）

HUD：`sample_batt()` 读 `TYPE=Battery` 的 psy；顶部画 `功耗 x.x W · xx%`，CPU 行带 `x.x W`。字体补了「功耗」等字。

### 刷上之后的实测（SSH）

```text
/sys/class/power_supply/qcom-battery/
  VOLTAGE_NOW ≈ 4.35 V          （接近满电）
  CURRENT_NOW ≈ 0.5–0.9 A       （放电，HUD + Wi-Fi）
  CAPACITY = 1                  （不准，见下）
  TEMP ≈ 40.5 ℃

/sys/class/power_supply/qcom-smbchg-usb/
  TYPE=USB  ONLINE=1  INPUT_CURRENT_LIMIT=100000（SDP 100 mA）

USB ACM 仍在：0525:a4a7
```

整机功耗大约 **2–4 W**（µA × µV / 1e9 → mW）。6.1 上放电时 `current_now` 为正，HUD 按这个符号处理。

**电量百分比是错的：** 4.35 V 实际接近满电，FG SRAM 里的 SOC 没校准，报 1%。电压/电流/瓦数可用，百分比先当参考。

## 2. HUD：英文 Memory 重叠、0.3 GB、百分比硬跳

代码：`initramfs/gemini-status.c`。只重编 boot.img。

### 2.1 英文 “Memory” 盖住后面的数字

标题字体（44px）里 `Memory` 宽约 168px，从 x=56 画到约 224。副标题 `0.3 GB / 2.6 GB` 写死在 x=200，于是重叠。中文「内存」短，看不出来。

改成 `draw_meter_head()`：副标题从 `56 + text_w(标题) + 28` 再画。GPU / CPU 行也走同一套。

### 2.2 「内存一直 0.3GB」不是 bug

机上 `free -h`：

```text
Mem:  2.6Gi  used 302Mi  available 2.3Gi
```

3GB 机，内核还留了一截，HUD 没用桌面，**占用约 300 MB 是真的**。英文重叠时总容量被挡住，看起来像只有 0.3。显示改成 `0.30 / 2.63 GB`（两位小数）。算法仍是 `MemTotal − MemAvailable`。

### 2.3 占用百分比一跳一跳

空闲 HUD **5 fps**，平滑常数却是 `tau ≈ 125ms`（`k = 1-exp(-dt*8)`）。每 400ms 采样一次才 `dirty()`，插值帧根本没画出来，条已经贴在目标上，看起来就是整数硬跳。

改动：

| 项 | 之前 | 之后 |
|----|------|------|
| 采样间隔 | 400 ms | 200 ms |
| 平滑 | `exp(-dt*8)` ≈ 125ms | `exp(-dt*2.6)` ≈ 380ms |
| 条还在跟上 | 不重绘 | 约 **18 fps**，追上再回 5 fps |
| 拖动手势 | 30 fps | 不变 |

`ease_meter()` 差值 < 0.05 时贴死，避免浮点抖着不降帧。

## 5. 把 Adreno 530 3D 救活

### 要解决什么

显示控制器（MDP）早就在扫 `fb0`，**不等于** 3D 能跑。HUD 发热来自 CPU 整屏 `write(fb0)`。dmesg 一直是：

```text
adreno b00000.gpu: error -5 initializing firmware qcom/msm8996/gemini/a530_zap.mbn
msm_mdp: gpu hw init failed: -5
```

`-5` = `-EIO`，出在 `qcom_scm_pas_init_image()`：TrustZone 拒签 zap 的 metadata。  
机上那份 17188 字节 `a530_zap.mbn` 的 md5 是 `e257835f…`，和 linux-firmware **APQ8096** 通用包相同。`scripts/build-initramfs.sh` 曾在 gemini 路径缺失时用 APQ8096 那份顶上。

Vulkan Turnip **不支持** A530（Turnip 从 a6xx 起）。3D 只能走 Mesa **freedreno GLES**。

### 固件从哪来

userdata 上 6.1 时代的 split zap（`.mdt/.b00/.b01/.b02`）已经被通用包盖掉。  
**还在机上的** Lineage vendor 分区 `cust`（ext4，label=`vendor`）：

```text
/tmp/mnt-cust/firmware/a530_zap.mdt   6684   md5 8435e7b6…
/tmp/mnt-cust/firmware/a530_zap.b00    148
/tmp/mnt-cust/firmware/a530_zap.b01   6536
/tmp/mnt-cust/firmware/a530_zap.b02   4900
/tmp/mnt-cust/firmware/a530_zap.elf  17188   md5 cfb8de3d…   ← 小米签名的合并 ELF
```

ELF 布局和 linux-firmware mbn 一样（3 个 phdr），只有哈希/签名不同。把 OEM `.elf` 复制成 DTS 要的 `a530_zap.mbn`。

### 落到哪里

| 路径 | 作用 |
|------|------|
| `inventory/firmware/qcom/msm8996/gemini/a530_zap.*` | 编进 initramfs `/lib/firmware` |
| `rootfs-overlay/lib/firmware/qcom/msm8996/gemini/` | 每次开机 overlay 覆盖 userdata，避免再被通用包盖掉 |
| 机上 `/lib/firmware/qcom/msm8996/gemini/` | 当时立刻生效（`/lib` → `/usr/lib`） |

`build-initramfs.sh`：**有 gemini 这份时不再用 APQ8096 顶替**。

这次只换固件，**没有改内核、没有进 LK**。SSH `reboot` 后 `msm.ko` 从 userdata 重新加载 zap。

### 救活之后的证据

```text
[drm] Initialized msm 1.13.0
loaded qcom/a530_pm4.fw / a530_pfp.fw / a530v3_gpmu.fw2
（不再有 zap -5 / gpu hw init failed）

/sys/kernel/debug/dri/0/gpu
  revision: 530 (5.3.0.2)
  ringbuffer id 0  rptr/wptr 走动

/sys/class/devfreq/b00000.gpu
  available: 133 / 214 / 315 / 401.8 / 510 / 560 / 624 MHz
  空闲 cur_freq 常停在 27 MHz（XO）；跑 3D 时到 133 MHz
```

用户态（清华源）：

```text
mesa-libgallium / libgl1-mesa-dri / libegl1 / libgbm1 / mesa-vulkan-drivers
kmscube / mesa-utils-bin / vulkan-tools
```

`timeout 3 kmscube -A`：

```text
EGL 1.5  Mesa Project
OpenGL ES 3.1 Mesa 26.0.8-1ubuntu0.3
vendor: freedreno
renderer: FD530
```

`vulkaninfo` 会失败：`device Turnip Adreno (TM) 530 is unsupported`。这是预期，不是回归。

HUD **仍然 CPU 写 fb0**，没有改成 GLES 合成。GPU 现在可以给 3D 程序（kmscube / 以后的 GBM 应用）用；Docker 通用计算帮不上（没有 CUDA/ROCm）。

`out/boot.img` 已重新打包，带上这份 zap。下次刷 boot 时 overlay 会把签名固件写回 userdata。
