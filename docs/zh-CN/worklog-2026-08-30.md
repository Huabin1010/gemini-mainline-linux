## 1. 硬件事实（不要再猜）

| 项 | 实测 |
|----|------|
| 面板 | JDI FHD R63452，command mode，`jdi,fhd-r63452`，复位 GPIO TLMM **8** |
| DCS `0x0A` power_mode | 工作态 **`0x38`**（不是 ginkgo 的 `0x9c`）。`0x28` 之后是 **`0x30`**。Linux 对 bit 的解码不可信 |
| 面板 ID `0xBF` | `02 3c 34 52` |
| 触控 | Synaptics **S3330 incell**，`i2c-2` `2-0020`，IRQ TLMM **125**，复位 TLMM **89** `GPIO_ACTIVE_LOW`，和面板共用模拟电源 |
| 背光 | PMI8994 WLED，灯由 HUD 管（亮屏先 warmup 再点灯） |
| DSI | 14nm PHY。时序 HFP 120 / HPW 16 / HBP 40，约 145444 kHz |
| 必须保留 | `MIPI_DSI_CLOCK_NON_CONTINUOUS`（去掉 → 黑屏但灯亮） |

**会毁掉模拟端 / 触控的操作：**

| 不要做 | 后果 |
|--------|------|
| 灭屏写 `0xec … 0x95` | 关掉 incell AVDD → I2C `EIO`、`rmi_set_page: -6`、`event3` 消失，直到面板 GPIO 复位（伴随白条） |
| 每次亮屏 GPIO 复位面板 | 右边缘白线簇 |
| 拆掉 14nm PHY 再发 DCS **`0x11`（exit-sleep）** | 列驱动白条簇；`0x18` → `0x38` |
| `rmmod msm` | oops |
| `fastboot reboot` 当「还在跑刚才的 ramdisk」 | 它刷的是**分区里的 boot**，不是上一轮 `fastboot boot` |

## 2. 为什么会出白条

incell 列驱动对 MIPI 模拟端很敏感。以前能看的亮屏路径是：**DSI PHY 一直开着**，只发 `0x28` / `0x29`，CRTC 继续扫最后一帧，只关 WLED。没有白条，也没有 GPU/DSI 休眠（灭屏约 **2.4 W**）。

为了 suspend，HUD 改为：先 `0x28`，再 `drmModeSetCrtc(fb=0)`。MSM 会 `host_power_off` + `phy_disable` + `regulator_bulk_disable`。14nm PHY 的 `CMN_CTRL_0` 被写成 `0`，`vdda`/`vcca`/`vddio` 掉电。再亮屏时 booster 只剩 **`0x18`**，驱动就发 **`0x11`** 把它拉回 `0x38`——这一下打到列驱动，右边出现白条簇。触控侧会注入 SYN，灭屏后几秒内可能被当成「点亮」。

只发 `0x29`、不发 `0x11`：画面/booster 停在 `0x18`，不对。

---

## 3. 做成的路径

**灭屏（电源键）：** HUD 先把 WLED 调到 0，再 `gpu_runtime_pin(0)`，gold CPU2/3 下线 + powersave，然后：

1. sysfs `panel_sleep=1` → 面板 **只发 DCS `0x28`**（不 `0x10`、不改 `0xec`）。
2. `SetCrtc(..., fb=0)`，EGL 解绑。
3. MSM：关 DSI **链路时钟**（PLL），`pm_runtime_put` → GPU / `994000.dsi` / MDP `runtime_status=suspended`。
4. **不** `regulator_bulk_disable` 主机 vdda/vcca/vddio；**不** `dsi_mgr_phy_disable`。PHY `CMN_CTRL_0` 灭屏时仍是 **`0xff`**。

**亮屏：** `SetCrtc` 用上一块 GBM fb；`enable()` 若已经 `inited`：**只发 `0x29`**，轮询到 `0x38`。不 GPIO 复位、不 `0x11`。HUD `gpu_runtime_pin(1)`，warmup 约 24 帧再点 WLED。灭屏后约 3 s 内忽略触控唤醒（`t_blank`），避免 PHY 恢复时的 incell 鬼点把屏点亮。

cmdline 去掉 `clk_ignore_unused pd_ignore_unused`，否则未用时钟闸不住。

## 4. 功耗（PMI8994 FG，`P = |I|×V`）

电量计绝对读数会抖 **±0.2～0.4 W**。sysfs `capacity` 不准（电压约 4.35 V ≈ 满电）。

| 状态 | 中位（约） | 说明 |
|------|------------|------|
| 亮屏 | **3.3～3.8 W** | GPU/DSI/MDP `active`，`0x38` |
| 灭屏（只关灯、DSI 仍扫） | ~**2.4 W** | 旧路径，无白条，不 suspend |
| 灭屏（PHY 全拆） | ~**1.9 W** | 有白条 |
| 灭屏（**现行**：时钟闸 + 模拟保持） | **~2.19 W**（1.93～2.66） | 无白条；相对亮屏少 **~1.3 W** |

灭屏剩余约 2 W：**不是面板在扫**。主要是 Wi‑Fi（ath10k）、USB gadget、Ubuntu（BT-Panel、npc、docker 等）、两颗小核，以及故意没关的 PHY 模拟电源。SSH / Wi‑Fi 开着时到不了最初想的 1.50 W。

`scripts/check-blank-power.sh`：灭屏 GPU/DSI/MDP `suspended`，`dsi0vco_clk` / `mdss_mdp_clk` / `gpu_gx_gfx3d_clk` enable **= 0**，PHY `CMN_CTRL_0=0xff`，亮屏 `0x38`，空闲 `/dev/input/event3` **0 字节**，无新的 `rmi_set_page failed`。

## 5. 关键文件

| 路径 | 作用 |
|------|------|
| `overlays/linux/drivers/gpu/drm/panel/panel-jdi-fhd-r63452.c` | `disable()` 只 `0x28`；resume 只 `0x29`；sysfs `panel_sleep` |
| `overlays/linux/drivers/gpu/drm/msm/dsi/dsi_host.c` | PLL enable 后再 `link_clk_set_rate`；灭屏不关 analog regulator |
| `overlays/linux/drivers/gpu/drm/msm/dsi/dsi_manager.c` | 已使能则不再 `reset_phy`；`phy_disable` 空操作 |
| `overlays/linux/drivers/video/backlight/qcom-wled.c` | LK 已开 sink 时跳过 CABC 重配 |
| `overlays/.../msm8996-xiaomi-gemini-local.dtsi` | 删 WLED OVP irq 和 `qcom,cabc` |
| `initramfs/gemini-status.c` / `gemini-status-gpu.c` | 灭屏序列、warmup、CPU idle、触控抑制、`gpu_runtime_pin` |
| `scripts/apply-overlays.sh` | 把上述 C 文件盖进 `linux/`（**overlay 才是源**） |
| `scripts/check-blank-power.sh` | 灭/亮屏自动验收 |
| `scripts/build-bootimg.sh` | cmdline **不再**带 `clk_ignore_unused` |

编面板模块：`make O=out/kernel M=drivers/gpu/drm/panel modules`，`.ko` 在 **源码树** `linux/drivers/gpu/drm/panel/`，不在 `out/kernel/`。`msm.ko` 同样：`M=drivers/gpu/drm/msm` 产物在 `linux/drivers/gpu/drm/msm/msm.ko`。不要把 `O=` 目录里过期的 `.ko` 拷进 initramfs。

迭代用 **`fastboot boot`**；确认后再 `fastboot flash boot`。进 LK：HUD **短按音量+**，或 SSH `setsid /usr/local/sbin/reboot-fastboot &`（不要短 timeout 砍 SSH）。出现 `18d1:d00d` 立刻 `fastboot -s <serial> flash boot out/boot.img && fastboot reboot`。`fastboot devices` 再跟第二条命令会和 LK 超时抢跑。

不要 `pkill -f 'fastboot boot'`：模式会匹配当前这条 shell。
